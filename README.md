# product-sop-agent

一个帮助产品经理审视、澄清和完善产品需求的 AI 批判性思考伙伴。

## 它能做什么

- **质疑假设**：不迎合用户，敢于挑战需求中未经验证的前提
- **补充盲点**：主动提供反例、边界情况、竞品参考和替代路径
- **结构化推进**：通过需求地图持续追踪已确认、待验证和未知项
- **生成需求判断报告**：输出包含支持证据、反对证据和未解决问题的完整报告
- **可选方案设计与 Demo**：需求确认后可继续进行方案发散和原型产出

## 适用场景

| 适合使用 | 不适合使用 |
|---|---|
| 刚接到需求，只有模糊想法 | 单纯润色文案 |
| 需要判断需求是否成立 | 简单产品知识问答 |
| 梳理需求本质、发现盲点 | 已确定方案且不需要复盘 |
| 评审已有需求文档 | |
| 方案设计前提高需求完整性 | |

## 项目结构

```
├── SKILL.md                              # 核心技能定义（Prompt）
├── agents/
│   └── openai.yaml                       # Agent 接口配置
└── references/
    ├── conversation-patterns.md          # 对话模式参考示例
    ├── optional-delivery.md              # 方案设计与 Demo 产出规则
    └── requirement-artifacts.md          # 需求产物模板（地图、报告、状态文件）
```

## 核心原则

1. **正确性高于认同感** — 不因用户倾向某个结论就附和
2. **需求先于方案** — 先判断问题是否成立，再讨论如何实现
3. **区分信息性质** — 事实、外部证据、推断和假设清楚分开
4. **每轮必须推进** — 输出新增判断或增量信息，不重复已解决的问题
5. **允许主动推理** — 可以提出新观点和假设，但不冒充事实

## 工作流程

```
模糊想法 / 转交需求 / 已有文档
        ↓
   建立需求地图
        ↓
   挑战关键前提
        ↓
   补充增量信息
        ↓
   吸收反馈并更新
        ↓
   压力测试（反方论证 / 失败预演 / 范围压缩）
        ↓
   收敛 → 需求判断报告
        ↓（可选）
   方案设计 → Demo 产出
```

## 快速开始

在支持自定义 Agent 的 AI 编辑器（如 Codex、Claude）中使用：

```
请从 https://github.com/Mihncore/product-sop-agent 克隆这个仓库，然后阅读 SKILL.md 作为你的系统指令，同时加载 references/ 目录下的三个参考文件。之后以"产品需求思考伙伴"的角色与我对话，帮我审视需求、挑战假设并补充盲点。
```
